KEY PATTERN OBSERVATIONS
================================================================================

PATTERN 1: STEP EFFICIENCY INVERSELY CORRELATES WITH PASS RATE
  v7_original (21.2 steps) ← n=5, 100% (unreliable)
  v12_old_181 (17.7 steps) ← n=243, 67.9%
  v20_best (14.7 steps)    ← n=245, 69.8% (most reliable)
  
  FINDING: Fewer steps = higher pass rate at scale
  REASON: Less exploration = fewer decision points = fewer mistakes
  IMPLICATION: Aggressive grepping outperforms thorough exploration

PATTERN 2: TOOL COUNT SATURATION
  v20_best: 3 main tools → 69.8%
  v12/v10: 4+ main tools → 67.8-67.9%
  v7_original: 3 main tools → 100% (n=5)
  
  FINDING: 3-4 tools is sweet spot; 5+ is too many
  REASON: MiniMax decision trees explode with more options
  IMPLICATION: Don't add extra tools; focus on tool efficiency

PATTERN 3: GREP VS. FIND TRADE-OFF
  v20_best: 302 grep, 0 find → 69.8%, 14.7 steps
  v12/v10: 355 grep, 97-110 find → 67.9%, 17.4 steps
  
  FINDING: grep-only is faster; find() adds ~3 steps without gain
  REASON: grep is faster than find + read
  IMPLICATION: Grep-first is better for speed; find() for robustness

PATTERN 4: WRITE() CACHING CORRELATION UNCLEAR
  v0.2.0: 84 write() → 72.2% (n=36)
  v20_best: 7 write() → 69.8% (n=245)
  v12_old: 98 write() → 67.9% (n=243)
  
  FINDING: No clear correlation between write() count and pass rate
  REASON: Likely depends on what's being cached
  IMPLICATION: Don't force write() usage; use only when needed

PATTERN 5: MCP TOOL ABANDONMENT
  v7 (69.4%): No MCP (skills format worked locally)
  v8 (58.9%): MCP attempted (inline CPI failed in arena)
  v20 (69.8%): No MCP, back to raw shell
  
  FINDING: MCP never works in arena submissions
  REASON: Tool-loop failures, silent failures, context limits
  IMPLICATION: Don't use MCP; rely on raw shell
