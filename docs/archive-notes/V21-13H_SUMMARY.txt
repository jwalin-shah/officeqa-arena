V21-13H EFFICIENCY ANALYSIS - EXECUTIVE SUMMARY
80.4% PASS RATE | 5.4 AVG STEPS IN PASSING | 9.4 AVG STEPS IN FAILING
================================================================================

THE FINDING:
v21-13h's efficiency is NOT about speed or sophisticated reasoning.
It's about CONFIDENCE and DECISION COMMITMENT.

Passing traces (5.4 steps): Extract answer → Write → Done
Failing traces (9.4 steps): Extract data → Reconsider → Recalculate → Uncertain

The 4-step difference is entirely due to AMBIGUITY SPIRALS in failing traces.

================================================================================
KEY METRICS
================================================================================

Reasoning Pattern Differences:
  Ambiguity mentions:  0.4 (passing) vs. 5.0 (failing) = 12.5x MORE in failures
  Reconsiderations:    2.6 (passing) vs. 12.4 (failing) = 4.8x MORE in failures
  Reasoning length:    1,242 chars (passing) vs. 2,274 (failing) = 1.83x LONGER

Workflow Differences:
  Passing: Question → File → Extract → Write → Summary (4-5 steps)
  Failing: Question → Grep → Find → Extract → Reconsider → Calculate → Uncertain (8-18 steps)

Step 3 Inflection Point:
  Passing: "I found the answer. [Quote]. This directly answers..."
  Failing: "I found the data. But I need to verify which interpretation..."
  
  By step 5, passing traces have written answer; failing traces still debating.

================================================================================
WHAT MAKES PASSING TRACES PASS
================================================================================

1. CONFIDENCE-FIRST EXTRACTION
   ✓ Parse question → Identify expected file → Read file → Extract
   ✓ No "could this mean..." language
   ✓ Commit to first interpretation
   
2. PAGE FILE PREFERENCE
   ✓ ALL passing traces read *_page_*.txt files when available
   ✓ Page files = extracted answer sections (no exploration needed)
   ✓ One read, direct extraction, no grep loops
   
3. DECISION CERTAINTY IN LANGUAGE
   ✓ "I found the answer" (not "I found data")
   ✓ Direct text quotes (not interpretations)
   ✓ "This directly answers" (not "this could mean")
   
4. ZERO RECONSIDERATION SPIRALS
   ✓ Message goes: message → observation → next action
   ✓ NO "wait, let me reconsider" after extraction
   ✓ NO verification loops after writing answer

================================================================================
WHAT BREAKS FAILING TRACES
================================================================================

1. AMBIGUITY LANGUAGE (5.0 mentions vs. 0.4 in passing)
   ✗ "Could this mean..."
   ✗ "Let me reconsider..."
   ✗ "I need to determine if..."
   ✗ "This is unclear whether..."
   
   IMPACT: Opens decision space → multiple interpretations → spiral

2. EXPLORATION BEFORE EXTRACTION
   ✗ Grep for keyword (Step 2) instead of reading page file
   ✗ Multiple tables appear → "which one is correct?"
   ✗ By step 4-5: already spent 2+ steps on exploration
   
   IMPACT: Lost commitment window; ambiguity takes over

3. MULTIPLE CALCULATION ATTEMPTS
   ✗ First calculation done, but uncertain about interpretation
   ✗ Recalculate using different logic (Method 1, 2, 3)
   ✗ Each recalculation adds 500-1000 chars of reasoning
   
   IMPACT: 9 extra steps (uid0083) trying to solve uncertain question

4. VERIFICATION LOOPS AFTER COMMITMENT
   ✗ Write answer in step 14
   ✗ Verify in steps 15-18
   ✗ Verification never changes answer (commitment too strong)
   
   IMPACT: Wasted steps; mind already made up

IMPLEMENTATION: 3 CRITICAL CHANGES
================================================================================

CHANGE 1: ADD CONFIDENCE PRINCIPLE (TOP PRIORITY)
  ✓ Add to prompt: "Confidence in first extraction > second-guessing"
  ✓ Explicitly forbid: "could mean", "let me reconsider", "unclear"
  ✓ Enforcement: "Once you extract a value, write it. Do NOT recalculate."
  
  MEASUREMENT: Track these words in reasoning. Should be < 2 per passing trace.
  
CHANGE 2: PAGE FILE FIRST (REINFORCE EXISTING)
  ✓ Add to prompt: "If page file exists (*_page_*.txt), READ ONLY THAT FILE"
  ✓ No grep, no exploration, no "let me search for..."
  ✓ Page files = answers. TXT files = noise.
  
  MEASUREMENT: Page file traces should be 1-2 steps shorter than TXT traces.

CHANGE 3: BLOCK VERIFICATION LOOPS (NEW)
  ✓ Remove: "After answering, double-check your work: load('verify')"
  ✓ Add: "Verification is OPTIONAL and only for unit-checking (thousands vs. millions)"
  ✓ Message: "If you must verify, understand reconsideration after writing rarely helps"
  
  MEASUREMENT: Traces with >2 verification steps should fail.
