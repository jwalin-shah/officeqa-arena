4. WHAT WORKS (PROVEN WINNERS)
================================================================================

CONFIRMED HIGH-VALUE (all top versions use these):

1. FY/CY EXPLICIT GUIDANCE
   - R10 analysis: 52% of failures were fiscal/calendar year boundary errors
   - v20_best includes: "FY pre-1977: Jul-Jun, FY post-1976: Oct-Sep, CY: Jan-Dec"
   - Impact: Eliminates entire failure category

2. GREP-FIRST STRATEGY
   - v20_best: 302 grep calls (most any version)
   - Fast table location before extraction
   - Reduces false positives from wide tables

3. EARLY ANSWER WRITING
   - "Write your best guess immediately after finding data"
   - Prevents "no answer" penalties
   - Allows iterative refinement

4. TODO-WRITE PLANNING
   - All top versions use todo_write(100+)
   - Forces decomposition: read question → explore → extract → compute → verify
   - Improves problem structuring

5. PYTHON3 INLINE COMPUTATION
   - All versions heavy on python (450-565 calls)
   - Direct shell access to `python3 -c` or full scripts
   - No MCP tool wrapper needed

6. SHORT PROMPTS (19-21 lines)
   - v20_best: 19 lines (14.7 steps)
   - v12_old: 21 lines (17.7 steps)
   - Longer prompts = more turns wasted = lower efficiency

7. VERIFY STEP
   - load("verify") after writing answer
   - Documented to flip 50% of wrong-answer tasks
   - v20_best doesn't use it → leaves 5-8 points on table

================================================================================
5. WHAT DOESN'T WORK (PROVEN FAILURES)
================================================================================

CONFIRMED HARMFUL (versions using these underperformed):

1. MCP TOOLS
   - Status: Available in all recent versions (r8+)
   - Usage: ZERO MCP calls across all 245 v20_best traces
   - Conclusion: Tools are called via raw shell instead
   - Why: MiniMax tool-loop failures, simpler to use shell directly

2. PRE-BUILT SQL DATABASE
   - Status: r8+ tarballs include /installed-agent/db.sqlite (68MB gzipped)
   - Usage: Never queried in v20_best traces
   - Conclusion: Raw file grep > DB approach
   - Insight: DB loses 50% of data format variation (from memory notes)

3. SKILLS WITH FORMULAS
   - Status: v7 had 5 SKILL.md files for CPI, FY detection, etc.
   - Score: v7=69.4%, but then regressed in v8-v20
   - Conclusion: Skills format broken in arena, dropped by v8
   - Why: Skills work locally, fail silently in arena submissions

4. NEGATIVE INSTRUCTIONS
   - Tested: "NEVER curl" to prevent API calls
   - Result: v8 had 248 curl attempts vs v7's 204
   - Conclusion: Negative framing backfires; MiniMax does opposite

5. FEW-SHOT EXAMPLES
   - A/B test: Few-shot examples in prompt
   - Result: 55% pass rate vs 70% baseline
   - Conclusion: Examples anchor MiniMax on patterns, reduces generalization

6. VERBOSE BRIEFINGS
   - Finding: Verbose context before question causes MiniMax to override correct answer
   - Solution: Answer-first, compact format works better
   - Example: v8 verbose beat by v9 compact

7. COMPLEX TOOL LOOPS
   - Issue: MiniMax can't maintain tool state across steps
   - Tried: Tool → file → tool → file chains
   - Works: Single-purpose tool calls or direct shell

8. KEY INSIGHTS FOR IMPLEMENTATION
================================================================================

INSIGHT 1: Step Efficiency Matters at Scale
  - v20_best: 14.7 steps → 69.8%
  - v12_old_181: 17.7 steps → 67.9%
  - Implication: Aggressive grepping beats thorough exploration

INSIGHT 2: Verify Step is Highest-Leverage Single Improvement
  - Documented: Flips 50% of wrong-answer tasks
  - Cost: ~1 additional turn
  - Gain: ~2-4% on top of baseline
  - v20_best doesn't use it → opportunity for +2-4%

INSIGHT 3: Tool Count has Sweet Spot
  - Too few (0-2): Misses exploration opportunities
  - Sweet spot (3-4): shell, todo, write
  - Too many (5+): Confusion, MiniMax makes poor choices

INSIGHT 4: FY/CY Guidance is Essential
  - R10: 52% of failures were time-period confusion
  - All R10+ versions include explicit rules
  - Must never remove from prompt

INSIGHT 5: ~70% is Realistic Ceiling
  - 41 always-fail tasks (inherently hard)
  - 56 flaky tasks (strategy-dependent)
  - 149 consistently passing tasks
  - 246 total - 41 always-fail = 205 achievable → ~70% = 143 passes

INSIGHT 6: Model Doesn't Matter, Strategy Does
  - All versions use same model (MiniMax M2.5)
  - Range: 57.6% to 100% (by strategy, not model)
  - No benefit to testing GPT-4, Claude, o1-preview
